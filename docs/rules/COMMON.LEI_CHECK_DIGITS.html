How the status is set

  • Missing: no section that reads LEIs on its own (below) holds an LEI-shaped code (18 upper-case letters or digits and two check digits) as written, and no section issuer, offeror or trading_platform_operator has text other than a placeholder. A malformed code, or an LEI-shaped code elsewhere that fails its check digits (below), is named in the finding but does not change this status.
  • Review: an LEI-shaped code that is read fails the ISO/IEC 7064 MOD 97-10 check digits; an LEI-like code that is read is malformed; or no section that reads LEIs on its own holds an LEI-shaped code as written while a party section has text, since point 5 allows another identifier required pursuant to applicable national law in place of the LEI. A section reads LEIs on its own if it is issuer, offeror or trading_platform_operator, names an LEI label (LEI or LEIs, legal entity identifier or ID, Rechtsträgerkennung, in any case, also split by hyphens, dashes or line ends) or holds an LEI-shaped code with a letter. A draft with such a section, or whose file text names a label or holds such a code, is read in all its text: every section and, for a PDF, DOCX, Markdown, XHTML or HTML file, the text outside the sections (headings, tables, text boxes, headers and footers, text in no section). A DOCX, PDF, XHTML or HTML file that holds text a reader cannot see is also read as a reader sees it, without that text (see the limitations), and a code that this reading alone finds malformed or with failing check digits is named as standing in the text as a reader sees it. Each text is read as written and, where markup or a character reference changes it, as a Markdown or HTML renderer shows it (comments, tags, emphasis, code and link markup removed, &nbsp; and other references replaced by their characters). There every LEI-shaped code, a 20-digit number included, has its check digits checked, and every LEI-like code counts, wherever it stands: one run of 16 to 24 letters and digits of any script that holds a digit or is in ASCII capitals, or a longer run with a digit that a glued LEI (up to 28 characters) or a glued word explains; groups joined by one to three spaces, hyphens, dashes or line ends, with at most one hyphen or dash and one line end between two groups, and by any number of invisible characters (zero-width spaces, bidirectional marks and other format characters), that together hold at least 16 and hold a digit or all have one length; or two pieces with letters and digits of a code that a table cell wraps from a line that names an LEI label, or the line before one, onto the next line. A word of letters only with a lower-case letter or a letter outside ASCII joins only beside a group of its length with a digit. An LEI-like code is malformed unless it is one run that is LEI-shaped as written. So a code is malformed if it has 16 to 19 or 21 to 24 characters, is in lower case, has a letter where a check digit belongs or a character outside ASCII, is glued to LEI or to a word, is split into groups, or is wrapped in a table cell.
  • Pass: a section that reads LEIs on its own holds an LEI-shaped code as written, every LEI-shaped code that is read, as written or as shown, has valid check digits and no LEI-like code is malformed. No registry is asked.

Limitations

  • Reads every section of the draft; findings are anchored to the issuer section.
  • Works offline on the characters of each code. It does not confirm that an LEI is registered, current or held by the entity the draft names.
  • Status and severity are fixed by the rule. A draft cannot waive or downgrade them.
  • Does not recognise the other identifiers that point 5 allows in place of the LEI, so a draft without any LEI goes to review once a party section has text. Once the draft gives one LEI, a party section without an LEI of its own does not change the result.
  • Reads the sections and, for a document file, the text its loader extracts. Text the loaders do not extract is not seen: in a DOCX, footnotes, endnotes, comments, deleted text as Word writes it (w:delText), field codes and text in charts, SmartArt or images; in a PDF, text that is not extracted (images, scans, annotations, form fields); in XHTML or HTML, the head, scripts, styles and attribute values, and CDATA sections, which the HTML parser drops (a code inside <![CDATA[…]]>, or the part of a code inside one, is not read); in a JSON draft, anything outside its sections, such as the title. An entity that an XHTML or HTML document declares in its own DTD is not expanded, so a code given through one is not read. A DOCX, PDF, XHTML or HTML file is read twice: with all its text, hidden text included, and as a reader sees it, without the text that the loader finds a reader cannot see. A code that is malformed or fails its check digits in either reading keeps the rule from passing, so hidden text that the second reading leaves out cannot complete a code the document shows malformed, split it into groups that are no LEI-like code, or glue it to other text. Left out are: in a DOCX, text inside a tracked deletion (w:del) or moved away under tracked changes (w:moveFrom), and a run, with everything in it such as a text box, that is hidden (w:vanish), set in a font under 1 pt (w:sz), or white or nearly white (w:color, each colour channel at least 95 %) with no highlight (w:highlight) or shading (w:shd) behind it, each as set on the run, else in its character style, else in its paragraph's style (or a style these are based on), else in the document defaults; a paragraph whose mark is deleted, moved away or set to w:vanish runs on into the next one. What stays joins as Word shows it with every tracked change accepted, so a code split between a run and a content control, a tracked insertion, a field result or a smart tag reads as one, in every paragraph, table, header, footer and section. In a PDF, text drawn in text render mode 3 or 7, text whose render mode paints only in white or nearly white (a colour set with g, rg or k, their stroke forms, or sc and scn in a device colour space; each grey or RGB component at least 0.95, each CMYK one at most 0.05), and text in a font under 1 pt on the page (its size scaled by the text matrix, the current transformation matrix and any form XObject's matrix). In XHTML or HTML, an element that its style attribute sets to display:none, or that carries the hidden attribute and whose style attribute sets no display, with all its content; the content of an element set to content-visibility:hidden or hidden="until-found"; and the text of an element set to visibility:hidden or collapse, or inside one without visibility:visible of its own, which counts as a space because it keeps its place. Hidden text that is not told apart is still read as if shown, so a fragment there can complete a code the document shows malformed, or split it into groups that are no LEI-like code, and the rule passes unless something else keeps it from passing: in a DOCX, text in a font of 1 pt or more, in the colour of a coloured background, behind an image or off the page; in a PDF, text in a font of 1 pt or more, under other content (such as a white filled rectangle), outside the clipping path or off the page, transparent text, and white text in a pattern or in a colour space other than the device ones; in XHTML or HTML, text that a style sheet hides (a <style> element or linked CSS, through a class or any other selector), text that other properties hide (opacity, colour, font size, position, clipping), the content of a closed <details> element and text that scripts hide. Text the second reading leaves out that a reader does see can only add a review, which fails safe: in a DOCX, white text on paragraph or table cell shading or a coloured page, and a run whose paragraph style and character style both set w:vanish, which Word shows; in a PDF, white text on a coloured background. The section text of a DOCX holds only the runs and hyperlinks that stand directly in a paragraph of the body, so it leaves out text in a tracked insertion or at a move's new place (w:moveTo), a content control, a field result (w:fldSimple), a smart tag, custom XML or a text box. A valid code that such text completes with four characters or fewer reads as malformed in the section text, and the rule goes to review, which fails safe; with five or more, what stays in the section text is no LEI-like code and the rule passes. A malformed code that is no LEI-like code in the text as written or as shown is not seen either: one run of fewer than 16 letters and digits, or of more than 24 (28 for one with a digit after a glued LEI) that no glued word explains, as when a code has lost or gained five or more characters or has digits glued to it; groups that together hold fewer than 16; a run of letters only with a lower-case letter or a letter outside ASCII, which reads as a word; groups split by any other character, such as a full stop, a slash, a comma, a bullet or an underscore that a renderer shows, by more than three characters other than invisible ones, or by two hyphens or dashes or two line ends (a blank line); a code split into groups where such a word stands beside no group of its length with a digit; groups in ASCII capitals without a digit and of different lengths; or a code that a table cell wraps where a piece holds no letter or no digit or is split into groups, where neither line names an LEI label (as in a PDF party table whose LEI label stands only in its header row, above the row in which the code wraps), where other lines stand between its pieces, or where the code wraps over more than two lines. Markup inside text that a renderer does not show, such as an HTML comment or a link target, is read as written only. Every LEI-like code in a draft that reads LEIs counts, wherever it stands, so an IBAN, a long number in groups, a placeholder such as XXXXXXXXXXXXXXXXXXXX, a reference number of 16 to 24 letters and digits, an address or a heading in capitals with a digit in it, a word of 16 to 24 ASCII capitals in a heading or in text, numbers in neighbouring table cells that join, two codes with letters and digits on a line that names an LEI label and the next line, or a valid LEI glued to LEI or to a word or split into groups (also by markup, as written) gives Review too, which fails safe. A code that the file text and a section quote with different neighbours is named twice, and once more where the file's text as a reader sees it quotes it with other neighbours.
